## Changes and performance scope

Only one download audit can run at a time per local runtime; a second receives429 DOWNLOAD_BUSY and a retryable message. This bounds concurrent archive verification and native audit processes; HTTP response buffers remain alive until the transport consumes them. A finally block releases the slot after errors or success. Every permitted download still checks fresh source/attempt/mode/generated bytes/captures/ZIP; no cached proof or relaxed evidence is introduced. Actual Node tests overlap real downloads, test failure release and repeat successful fresh audit.

Unsafe reserved-device upload names now fail before expensive conversion, matching existing packaging rejection. Preview capture membership changes from repeated list scans to a Set, keeping identical declared page availability and all source/capture hash checks. A synthetic6000-name/2000-page lookup experiment returned all6000matches in296.1231ms before and3.2154ms after. This measures name lookup only, not conversion speed or supported document capacity (default PDF admission is500pages).

Removed unused dashboard stages/resumable/stageIndex exports and its obsolete implementation-mirroring test. Session metadata now advertises one file and omits obsolete auth-mode/aggregate batch-byte fields. No current UI behavior/route/legacy strict proof gate was removed. Legacy offline service source/tests remain as explicitly historical recovery/regression material and are not started or installed by active setup; removing tested proof compatibility code would not simplify the active runtime safely.

## Security and output checks

Existing upload signatures/size/OOXML expansion/XML/macro/PDF-action guards, opaque private directories/path/symlink checks, fixed argv/no shell, timeout/RSS/output/disk monitoring, cancellation/expiry and fresh download checks are retained. Current tests cover unsafe input, traversal/origin rejection, source/artifact/proof tampering, ZIP CRC/membership, cancellation and real Windows reader-lock completion. Native resource monitoring is application-level, not an OS sandbox. [Deployment boundaries](deployment.md) document public-hosting controls separately; no new infrastructure/account setup is imposed on local conversion.

Archives retain exactly one mode-correct document plus referenced root assets; no source PDF/DOCX/report/JSON/CSS/JS/screenshot enters the user ZIP. Standard preserves selectable native text; EDGAR keeps its local-profile and unsupported-geometry boundary. Six genuine saved HTTP ZIPs were rechecked in the final browser suite. Supplied complex EDGAR sources still fail clipping instead of creating misleading output. Neither exact pixels nor SEC acceptance is claimed.
