# Current SEC EDGAR validation contract

Authority is the supplied EDGAR Filer Manual VolumeII version78, dated September14,2026: [manual](../tests/fixtures/edgarfm-vol2-v78.pdf), source hash in [fixture inventory](fixture-inventory.json). Stage6 read the actual Chapter5 requirements; [renderer documentation](edgar-renderer.md) records relevant pages, source research, supported markup and unresolved interpretation boundaries.

Standard Mode is the default and uses modern `.html`; EDGAR restrictions never restrict Standard. EDGAR Mode uses a separate normal-flow `.htm` renderer over the same authoritative PDF model. Names are deterministically SEC-compatible, assets are local JPG/GIF, and actual markup, literal CSS grammar, attributes, character references, links and decoded graphic bytes are validated. Nested tables, JavaScript, SVG/modern body elements, remote graphics/fonts/stylesheets, iframes and unsupported objects are rejected. ZIPs include only the document and referenced assets at root.

The current `efm78-flow-css2-v1` implementation makes an explicitly documented local interpretation of STYLE/MANY and HTML4 common attributes; it is not an exhaustive SEC-approved CSS permission list. The profile, implementation and grammar are hashed and checked again at packaging/download. Source policy is [flow_profile.py](../packages/converter/sec_validation/flow_profile.py); actual validators remain [separate from legacy strict proof](sec-validation-engine.md). No strict unresolved permission is silently promoted by model inspection, browser success or a current local-profile pass.

Actual DOM/print disclosure/page/word geometry and raw pixel evidence are retained. Current zero-width ligature handling is a narrow typography extraction exception with warning, not additional SEC markup permission. Clipping/overlap/unsupported geometry may require failure instead of corrupted output. The authorized [rectangular-layout repair](edgar-rectangular-layout.md) provides a separate hashed edgar_layers_v1 policy for supplied complex fixtures and independent clipped image/text cases. It preserves rectangular clips and reports vertical/sidebar reflow and forbidden-link inactivation. Curved/unsupported cases still fail clearly; original strict/flow-v1 defaults remain unchanged.

No authorized SEC test or live submission has occurred, and no SEC acceptance is claimed. Local validation is a documented implementation check; any actual filing still requires the authorized filing workflow. This app never requests filing credentials or transmits submissions. See [current tests](integration-testing.md), [remaining limits](limitations.md) and [earlier detailed research](history/pre-stage10-sec-compliance.md.txt).
