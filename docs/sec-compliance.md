## Uncertainties and conservative handling

The attribute table references LINK while the permitted document/body tag tables omit it; do not permit LINK by inference. IMG width/height and FONT face are common browser capabilities but not clearly included for those parents in the table; leave unresolved rather than invent an allowance. TR width appears in a body-tag note but is omitted from the attribute table: record it separately. The MANY designation needs an approved per-tag expansion. Handle named bookmarks and URL parsing without assuming browser URL normalization makes a URL safe: reject traversal, credentials, misleading hostnames, network-path references, encoded scheme tricks and unresolved fragments.

No production strict rules profile is approved yet. Confirmed rule entries can drive Stage 5 design, but Stage 6 must resolve required unknowns, validate source bytes before parser repair (notably auto-inserted TBODY), inspect actual files, and produce rule-specific diagnostics. Do not classify all valid historical manual constructs as generic HTML failures. Product security restrictions must be labeled separately.

## Diagnostic contract and authorized SEC checks

Each failure contains stable code, description, affected file/element, rule ID/manual section where applicable and suggested remediation. Report local validation as local only. Human filing operators may use EDGARLink Online Doc Validation and an authorized TEST submission under their filing account and applicable form workflow, inspect the actual SEC response, and reconcile it with local diagnostics. This project does not transmit filings or obtain credentials. No test or live submission was made in Stage 1.

Stage 5 adds a [proposed generator profile](compliance/efm-v78.stage5-candidate.json) with manual-listed tags and candidate style vocabulary. This does not release or amend the v78.1 design registry and does not approve CSS/MANY/Unicode interpretation. No executable SEC validator was implemented early. All candidate compliance flags remain false pending Stage 6 actual-file validation.

Stage 6 implementation: [v78.2 executable local registry](compliance/efm-v78.2.rules.json) and [engine behavior/research](sec-validation-engine.md). The historical v78.1 design profile is unchanged. Confirmed-rule checks, strict product restrictions and unresolved applicable permissions are separately identified. Style/MANY uncertainty is not waived; current styled candidates fail. PAGE/R exceptions and supplementary SEC formatting guidance are recorded explicitly. Real graphic decoding, source-bound normalization and whole encoded submission context checks are implemented. No authorized EDGAR submission or SEC acceptance occurred.
