# Limitations and open qualification work

- Stage 2 adds a runnable FastAPI backend, durable job management, safe upload admission, local private storage, outbox dispatch and Celery admission infrastructure. There is no conversion engine, frontend, production deployment or downloadable filing package yet. Valid uploads stop explicitly at `blocked / awaiting_conversion_engine`.
- No revision acceptance, DOCX-to-PDF conversion, HTML reconstruction, SEC validator or visual comparison has been executed. Admission and fixture inspection are not proof that a renderer can reproduce Word. Download and preview endpoints intentionally deny unavailable artifacts; no successful conversion is simulated.
- Initial DOCX role labels contradicted the detected revision inventories. The user subsequently updated fixtures and current roles agree. The final inventory and reference findings record the evidence; never infer an accepted baseline solely from `(1)` in a name.
- The PDF's source mapping to an accepted DOCX must be established during Stage 3. Page count and geometry alone do not prove identical disclosure or layout.
- Commercial SDK licensing, font licenses/availability, revision/story coverage, platform support and all-page fidelity are unqualified. LibreOffice is a separately tested fallback, not an equivalent Word layout engine.
- No arbitrary document can be promised pixel-perfect EDGAR HTML. Rotated text, complex overlapping drawings, font metrics and legal markup restrictions can make strict reconstruction impossible. Such jobs must fail with diagnostics.
- The supplied manual does not provide a complete CSS property/value list in the inspected sections. MANY attributes, legacy character-reference ambiguities and conflicting attribute examples need explicit resolution before a strict profile is enabled.
- A standalone HTML/image ZIP is not a full EDGAR submission. Form-specific requirements, MIME-expanded aggregate limits, required exhibits, Inline XBRL and filing-fee data are outside this plain-HTM converter's certification scope.
- No authorized SEC TEST submission or acceptance evidence exists. Local checks must never be described as SEC acceptance.
- Git was unavailable on PATH during Stage 1. Stage 2 located the installed executable and used read-only status/diff; the user's existing README title edit was preserved. No agent Git write operations were performed and no repository was initialized by the agent.
- Live Redis/PostgreSQL services and Linux prefork workers are not available in this Windows workspace. Real-service tests are opt-in; in-memory Celery transport and SQLite tests do not certify them. Deployment must enforce private temporary spools, disk/connection quotas, Windows ACLs or POSIX access controls, TLS and process/network isolation. API admission deadlines are cooperative; process sandbox enforcement remains Stage 11.
- Schema initialization is explicit v1 creation/provisioning, not an incremental migration framework. No newer schema is silently upgraded. Global staging disk quotas and remote object storage are not yet implemented. The current test client emits a Starlette deprecation warning for the pinned httpx compatibility path; functionality is verified but that test dependency path will need migration.
