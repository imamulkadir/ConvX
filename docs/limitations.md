# Current limitations

This page describes the active simplified runtime after Stage10. Earlier multi-service and strict-reference limitations are preserved in [history](history/pre-stage10-limitations.md.txt); they are not current startup instructions.

- Supplied complex prospectus DOCX/PDF fixtures now have a source-associated rectangular EDGAR strategy. Vertical marginal text is reflowed as horizontal notes in vacant source-derived page bands, including full retention of clipped text; the UI warns about orientation/position/visibility differences. Forbidden external link destinations become inactive with labels preserved. Curved/unsupported clipping and other unsupported geometry still fail; no universal-layout claim is made.
- EDGAR checks use a separately hashed local CSS2/HTML4 interpretation. They never grant legacy strict proof or establish SEC acceptance. No authorized EDGAR test/live submission has occurred. Restricted flow cannot reproduce every clipping, overlap, rotation, table or mixed-size print layout; unsupported cases fail explicitly.
- Standard retains selectable native SVG text/paint, embedded CSS and local assets. Measured browser font/rasterization/pixel differences remain. Source text and geometry checks are evidence of those specific checks, not proof of identical pixels or complete semantic reconstruction.
- Free LibreOffice exports accepted DOCX to the authoritative PDF. Microsoft Word layout equivalence is not verified. Source tracked changes are accepted in a copy; the uploaded original remains unchanged. Local-font substitutions and unavailable embedding rights can affect appearance.
- Image-only pages are detected and retained as source graphics. OCR is not installed/integrated; no searchable text is invented or falsely verified. Font mappings, annotations, exotic effects and ambiguous layout/reading-order associations can require explicit unsupported diagnostics.
- Default limits include20MiB uploads,500PDF pages,2000pt page dimensions, bounded native render pixels/resources and whole-process deadline/RSS/disk limits. Complex documents can exceed those budgets. Monitoring is cooperative/application-level; no universal hostile-document OS sandbox is claimed.
- Runtime is one local Next process with local Python/native tools, one active conversion and one active download audit; extra simultaneous downloads receive retryable429. It is not a distributed/serverless/multi-user production platform. Public hosting and non-Windows platform behavior need separate qualification.
- Current temporary jobs expire after24hours, and clearing a job revokes download/recovery. Unknown/corrupt directories are preserved rather than recursively deleted by guessing ownership; private storage may need operator inspection if repeated failures fill it. Job IDs are private document-access capabilities.

See [actual tests](integration-testing.md), [final review](stage10-review.md), [runtime/setup](simplified-runtime.md), [Standard](standard-renderer.md), [EDGAR](edgar-renderer.md) and [ZIP](zip-packaging.md). No premium SDK/external conversion service or infrastructure account is required.
